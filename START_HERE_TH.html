ติดตั้ง SMART GRADE PRO TH บน Cloudflare + GitHub

ชุดนี้เป็นระบบใหม่สำหรับ Cloudflare ไม่ใช่ไฟล์ที่นำไปวางต่อท้าย Apps Script เดิม เริ่มใช้งานบน URL ใหม่หลังติดตั้งและนำเข้าข้อมูล ส่วนระบบ Sheets เดิมยังเปิดไว้ตรวจเทียบได้

วิธีที่ 1: ผ่านหน้าเว็บ GitHub และ Cloudflare

1. เตรียมไฟล์ต้นฉบับ

  1. ดาวน์โหลด ZIP แล้วคลิกขวา > แยกทั้งหมด
  2. เปิดโฟลเดอร์ SMART_GRADE_CLOUDFLARE จะเห็น package.json, wrangler.jsonc, src, public, migrations และ scripts
  3. เปิด START_HERE_TH.html ด้วย Chrome เพื่อดูขั้นตอนนี้แบบอ่านง่าย
  4. ใช้ไฟล์สะอาดที่แตกจาก ZIP สำหรับอัปโหลด GitHub อย่าอัปโหลด node_modules, .wrangler, .dev.vars หรือ JSON ข้อมูลนักเรียนที่ส่งออกมา

2. สร้างที่เก็บโค้ด GitHub

  1. เข้าบัญชี GitHub ของครู กด + > New repository
  2. ตั้งชื่อ เช่น smart-grade-pro-th เลือก Private แล้วกด Create repository
  3. เลือก uploading an existing file หรือ Add file > Upload files
  4. อัปโหลด สิ่งที่อยู่ภายใน โฟลเดอร์ SMART_GRADE_CLOUDFLARE ให้ package.json อยู่ระดับแรกของ repository
  5. ตรวจว่ามี .gitignore และ package-lock.json ด้วย แล้วกด Commit changes
  6. หากอัปโหลดโฟลเดอร์ชั้นนอกไปแล้ว ต้องตั้ง Root directory ใน Cloudflare เป็นชื่อโฟลเดอร์ชั้นนอกนั้น แนะนำจัด package.json ไว้ระดับแรกจะง่ายกว่า

3. สร้างฐานข้อมูล D1

  1. เข้า Cloudflare Dashboard > Storage & databases > D1 SQL database
  2. กด Create database ตั้งชื่อ smart-grade-pro-th แล้วสร้าง
  3. คัดลอก Database ID จากหน้าฐานข้อมูล
  4. กลับ GitHub เปิด wrangler.jsonc > รูปดินสอ เปลี่ยน database_id จาก 00000000-0000-0000-0000-000000000000 เป็นค่าจริง
  5. ให้ database_name ตรงกับชื่อฐานที่สร้าง และ name เป็นชื่อ Worker ที่ต้องการ เช่น smart-grade-pro-th แล้ว Commit
  6. กลับหน้า D1 > Console เปิดไฟล์ migrations/0001_initial.sql ด้วย Notepad
  7. คัดลอก SQL ไปวางและกด Execute ถ้าหน้าคอนโซลรับทีละคำสั่ง ให้รันทีละคำสั่งที่จบด้วยเครื่องหมาย ; รวม 7 คำสั่ง
  8. หลังทำสำเร็จจะมี app_meta, records, write_guard, private_settings, rate_limits และ pending_files

4. เชื่อม GitHub แล้วเผยแพร่ Worker

  1. Cloudflare > Workers & Pages > Create application เลือกเชื่อม GitHub repository
  2. อนุญาตการเข้าถึงเฉพาะ repository ของระบบคะแนน แล้วเลือก smart-grade-pro-th
  3. ตรวจว่าใช้ Workers ไม่ใช่การอัปโหลดเว็บ HTML อย่างเดียว
  4. Root directory เป็นระดับที่มี package.json
  5. Build command: npm run build
  6. Deploy command: npx wrangler deploy
  7. กด Deploy รอสำเร็จ และเปิด URL ที่ Cloudflare แสดง
  8. หากขึ้นว่ายังไม่ได้ตั้งค่าบัญชีครู ให้ทำขั้นตอน Secrets ด้านล่าง
  9. หากมี Worker อยู่แล้ว ให้เลือก Worker นั้น > Settings > Builds > Git repository เพื่อเชื่อม GitHub สำหรับอัปเดตครั้งถัดไป

5. ตั้งค่าบัญชีครูโดยไม่ต้องลง Node.js

  1. ในโฟลเดอร์ที่แตก ZIP เปิด GENERATE_SECRETS_OFFLINE_TH.html ด้วย Chrome บนเครื่องครู
  2. กรอกอีเมลและตั้งรหัสผ่านอย่างน้อย 12 ตัวอักษร กดยืนยันสองครั้งแล้วกดสร้างค่า
  3. เก็บรหัสผ่านที่ตั้งไว้สำหรับเข้าหน้าเว็บ
  4. ใน Cloudflare เปิด Worker > Settings > Variables and Secrets
  5. เพิ่มชนิด Secret ทั้งสามรายการ โดยคัดลอก Value จากเครื่องมือ:
    • ADMIN_EMAIL
    • ADMIN_PASSWORD_HASH
    • SESSION_SECRET
  6. วางเฉพาะค่าในกรอบ ไม่เติมเครื่องหมายคำพูด ไม่วางชื่อ ADMIN_ ซ้ำในช่อง Value
  7. กด Save and Deploy ตามหน้าจอ แล้วเปิดเว็บใหม่
  8. เข้าสู่ระบบด้วยอีเมลและรหัสผ่านที่ตั้งในข้อ 2

เก็บ SESSION_SECRET เดิมไว้เมื่ออัปเดตโค้ด เพราะใช้ตรวจลิงก์นักเรียนและเข้ารหัสสิทธิ์ Drive การเปลี่ยนค่านี้ทำให้ลิงก์เดิมต้องสร้างใหม่และต้องเชื่อม Drive ใหม่

6. ย้ายข้อมูลเดิมจาก Google Sheets

  1. เลือกช่วงเวลาที่ไม่มีการกรอกข้อมูลในระบบเก่า เพื่อให้ไฟล์ส่งออกเป็นข้อมูลชุดสุดท้ายก่อนย้าย
  2. เปิด Google Sheets เดิม > ส่วนขยาย > Apps Script
  3. กด + > สคริปต์ ตั้งชื่อ ExportToCloudflare
  4. เปิด scripts/ExportToCloudflare.gs ด้วย Notepad คัดลอกทั้งหมดไปวางในไฟล์ใหม่ แล้วบันทึก
  5. เลือกฟังก์ชัน exportSmartGradeForCloudflare แล้วกดเรียกใช้ อนุญาตด้วยบัญชีเจ้าของไฟล์
  6. ระบบสร้างไฟล์ JSON ใน Drive ของครู และแสดงลิงก์ในกล่องข้อความกับ Execution log
  7. เปิดลิงก์นั้น ดาวน์โหลด JSON ลงเครื่อง เก็บแยกจากโฟลเดอร์โค้ดที่จะอัปโหลด GitHub
  8. เปิดเว็บ Cloudflare > ย้ายข้อมูล > เลือก JSON > ตรวจไฟล์และแสดงจำนวนข้อมูล
  9. ตรวจจำนวนห้อง วิชา นักเรียน คะแนน และรายการเช็กชื่อ แล้วติ๊กยืนยันและกดนำเข้า
  10. ระบบนำเข้าได้เมื่อฐานใหม่ยังไม่มีนักเรียน/รายวิชา การส่งไฟล์เดิมซ้ำจะไม่เขียนทับข้อมูลที่เพิ่มภายหลัง
  11. รหัสไฟล์รูปเดิมอยู่ใน JSON แต่รูปยังอยู่ใน Drive เดิม ต้องเชื่อม Drive เพื่อเปิดรูปจากเว็บใหม่
  12. ลิงก์นักเรียนของระบบ Cloudflare ให้สร้าง/คัดลอกและแจกจากหน้าใหม่ ลิงก์ script.google.com เดิมยังเป็นของระบบ Sheets และไม่มีการซิงก์กลับจาก Cloudflare

7. เชื่อม Google Drive โฟลเดอร์เดิม

  1. เข้า Google Cloud Console ด้วยบัญชีครู สร้างหรือเลือกโปรเจ็กต์สำหรับระบบนี้
  2. APIs & Services > Library > ค้นหา Google Drive API แล้วกด Enable
  3. ตั้ง Google Auth Platform / OAuth consent screen: ชื่อแอป อีเมลติดต่อ และผู้ใช้ตามบัญชีโรงเรียน
  4. ถ้าใช้บัญชี Gmail ส่วนตัว ให้เลือก External และเพิ่มบัญชีเจ้าของโฟลเดอร์เป็น Test user ในช่วงทดสอบ
  5. Credentials > Create credentials > OAuth client ID > Web application
  6. Authorized redirect URI ใช้ URL เว็บจริงต่อท้าย /api/google/callback คัดลอกค่าที่แสดงในเว็บ > เชื่อมต่อ เพื่อลดการพิมพ์ผิด
  7. คัดลอก Client ID กับ Client secret ไปใส่ Cloudflare Worker > Settings > Variables and Secrets ชื่อ GOOGLE_CLIENT_ID และ GOOGLE_CLIENT_SECRET แล้ว Save and Deploy
  8. กลับเว็บ > เชื่อมต่อ > เชื่อมบัญชี Google Drive เลือกบัญชีเจ้าของโฟลเดอร์และอนุญาตสิทธิ์
  9. Drive scope ที่ใช้เป็นสิทธิ์จัดการ Drive ของบัญชีครู เพื่อใช้โฟลเดอร์และรูปเดิมได้ ตั้งแอปในโปรเจ็กต์ของครูและอ่านขอบเขตที่ Google แสดงก่อนอนุญาต
  10. ถ้า Google หรือผู้ดูแลบัญชีโรงเรียนกำหนดการยืนยันแอป/นโยบายเพิ่มเติม ให้ดำเนินการตามนั้น
  11. Google OAuth แบบ External + Testing มี refresh token อายุ 7 วันสำหรับ scope นี้ ต้องเชื่อมใหม่เมื่อหมดอายุ หากใช้งานต่อเนื่องให้จัดสถานะ Production/การยืนยันตามเงื่อนไข Google หรือใช้นโยบาย Internal ของโรงเรียนเมื่อมีสิทธิ์
  12. ในเว็บครู > จัดการ > เลือกวิชา/ห้อง > โฟลเดอร์เก็บรูป > บันทึก เพื่อทดสอบสิทธิ์
  13. ค่าเริ่มต้นเป็นโฟลเดอร์เดิม 1Y0SQQZVUi_WsAvN2WtuvN3rSPHJC-8_Y ตั้ง General access เป็น “จำกัด” ได้ นักเรียนใช้เว็บส่งรูป ไม่ต้องมีสิทธิ์แก้ไข Drive

8. ทดลองก่อนแจกทั้งห้อง

  1. เปรียบเทียบรายชื่อและคะแนนของหนึ่งห้องกับระบบเดิม
  2. เปิด คะแนน เลือกงานหนึ่งงานที่ใช้ทดสอบ ดูว่ารหัสนักเรียนตรงกัน
  3. สร้างลิงก์ส่งงานของวิชา/ห้อง เปิดอีกเบราว์เซอร์ เลือกชื่อและงาน แล้วทดลองส่งรูปของข้อมูลทดสอบ
  4. ตรวจสถานะ ไฟล์ Drive และคะแนนเต็มของงานที่ไม่มีคะแนน คะแนนที่ครูให้ไว้ต้องคงเดิม
  5. ลองเช็กชื่อคาบที่เกิดขึ้นจริงหนึ่งคาบ แล้วตรวจรายงานเวลาเรียน
  6. เมื่อผลตรงจึงสลับใช้งานจริงบนเว็บใหม่ และหยุดกรอกซ้ำสองระบบ

วิธีที่ 2: ตัวช่วยติดตั้งผ่าน Terminal

เหมาะเมื่อครูติดตั้ง Node.js LTS รุ่น 22.13 ขึ้นไปแล้ว

  1. เปิดโฟลเดอร์ที่มี package.json พิมพ์ powershell ในช่องที่อยู่ของ Windows Explorer แล้วกด Enter
  2. รัน npm install
  3. รัน npm run setup
  4. กรอกชื่อ Worker อีเมล รหัสผ่าน และเลือก cloudflare
  5. ทำตามเบราว์เซอร์ที่เปิดเพื่อเข้าสู่บัญชี Cloudflare
  6. ตัวช่วยสร้าง D1 ให้คัดลอก database_id ที่แสดงกลับมาวางใน Terminal
  7. ตัวช่วยเตรียมตาราง เผยแพร่เว็บ และตั้ง Secrets ทั้งสามให้
  8. นำโค้ดที่แก้ database_id แล้วเข้าที่เก็บ GitHub โดยใช้ .gitignore เพื่อไม่นำ .dev.vars และ node_modules ขึ้นไป
  9. เชื่อม GitHub กับ Worker ที่สร้างแล้ว และทำหัวข้อย้ายข้อมูล/Drive ตามด้านบน

ค่าใช้จ่ายและโควตา

Workers และ D1 มีแผน Free แต่มีโควตา CPU จำนวนคำขอ และจำนวนแถวอ่าน/เขียน การตรวจรหัสผ่านและถอดรหัสภาพ JPEG เป็นงาน CPU มาก จึงไม่รับประกันว่าภาพทุกขนาดทำงานใน Free ได้ ถ้าใช้จริงพร้อมรูปหลายคน แนะนำประเมิน Workers Paid จากปริมาณใช้จริงก่อนเปิดรับทั้งห้อง

เอกสาร Cloudflare ณ 26 ต.ค. 2569 ระบุ Free CPU 10 ms ต่อ invocation และตัวอย่าง Standard มี subscription 5 USD/เดือน อาจมีส่วนใช้เกินเพิ่มเติม ตั้ง CPU limit ใน Dashboard หากเลือก Paid ชุดนี้ไม่ได้เปิดการเรียกเก็บเงินหรืออัปเกรดแผนให้ครู

รูปใช้พื้นที่ Google Drive ของครูตามเดิม ไม่ได้ใช้ R2 และไม่ได้เรียกบริการ AI ที่มีค่า API

แก้ปัญหา

  • Build หา package.json ไม่พบ: ตรวจ Root directory ของ repository
  • ยังไม่ได้ตั้งบัญชีครู: ตรวจ Secrets ทั้ง 3 รายการและกด Save and Deploy
  • D1 ไม่มีตาราง: รัน migrations/0001_initial.sql ใน D1 ตัวที่ผูกกับ Worker
  • ไม่พบฐานข้อมูล: ตรวจ database_id และชื่อ Binding ต้องเป็น DB
  • รายชื่อไม่ขึ้น: เลือกวิชา/ห้องให้ถูก และลงทะเบียนนักเรียนในรายวิชานั้นแล้ว
  • เลือกชื่อได้แต่ส่งไม่ได้: ตรวจวันเริ่มเรียน การเชื่อม Drive และโฟลเดอร์รับรูป
  • Google redirect_uri_mismatch: URL ต้องตรงกับ Worker ที่ใช้ รวม https และ /api/google/callback
  • ส่งรูปแล้ว CPU exceeded: ทดสอบลดขนาดภาพ/จำนวนภาพ และประเมินแผน Workers ที่รองรับงานตรวจภาพ
  • เปลี่ยนข้อมูลจากอีกอุปกรณ์: รีเฟรชแล้วตรวจค่าก่อนกดบันทึกใหม่
  • Google token หมดอายุ: เชื่อม Drive ใหม่ และตรวจ OAuth Testing/Production
  • คืนข้อมูลสำรอง: ใช้ JSON นำเข้าในฐาน D1 ใหม่ที่ว่าง หรือใช้ D1 Time Travel ตามสิทธิ์ของแผน ไม่ควรล้างฐานจริงก่อนเก็บสำรอง

ใช้งานหลังติดตั้ง

เริ่มจากข้อมูลเดิม

หากย้าย Sheets ทั้งชุด ให้ทำเมนู ย้ายข้อมูล ก่อนเพิ่มรายวิชาหรือนักเรียนในฐานใหม่ ตรวจจำนวนและเทียบคะแนนหนึ่งห้องกับระบบเดิม จากนั้นเชื่อม Google Drive และสร้างลิงก์นักเรียนจากเว็บใหม่

เพิ่มข้อมูลใหม่

  1. เปิด จัดการ > เพิ่มรายวิชา กรอกชื่อ/รหัสวิชา ปี ภาคเรียน และครู เพิ่มแต่ละวิชาที่สอนแยกกัน
  2. เพิ่มห้อง เช่น ม.2/1 เพียงครั้งเดียว ห้องเดียวใช้กับหลายรายวิชาได้
  3. จัดการ > อัปโหลด Excel / CSV เลือกไฟล์รายชื่อ ตรวจจับคู่คอลัมน์ ดูตัวอย่าง แล้วนำเข้า แนะนำคอลัมน์ เลขที่, รหัสนักเรียน, คำนำหน้า, ชื่อ, นามสกุล, ห้อง, สถานะ เก็บรหัสเป็นข้อความเพื่อรักษาเลขศูนย์นำหน้า
  4. เลือกวิชาและห้อง > จัดรายชื่อในรายวิชา เลือกนักเรียนและวันเริ่มเรียน นักเรียนคนเดิมลงทะเบียนในวิทยาการคำนวณและคอมพิวเตอร์ได้โดยใช้รหัสเดิม
  5. จัดการ > เวลาแต่ละคาบ ตั้งเวลาโรงเรียนจริง แล้วเพิ่มตารางสอน เช่น จันทร์ คาบ 1 ถึง 2 วิทยาการคำนวณ ม.2/1

คะแนนและชิ้นงาน

เปิด คะแนน เลือกวิชา ห้อง และชิ้นงาน > เปิดกรอกคะแนน > กรอก > บันทึก ช่องว่างคือยังไม่ประเมิน ส่วน 0 คือให้ศูนย์แล้ว ระบบส่งรูปจะรักษาคะแนนเดิมรวมถึง 0

ชื่อชิ้นงานแก้แยกตามห้องได้ใน จัดการ หลังเลือกวิชา/ห้อง เช่น งานที่ 1 ของ ม.5/1 ชื่อการบ้าน ส่วน ม.5/2 ชื่อการเมือง ไม่จำเป็นต้องใช้ชื่อเดียวกัน

เช็กชื่อ

เปิด เช็กชื่อ เลือกวันที่ แล้วกดเช็กชื่อในการ์ดคาบเรียน เลือกมา/ขาด/ลา/สายและบันทึก ใช้ปุ่มทุกคนมาแล้วแก้เฉพาะคนขาดได้ กรณีไม่มีคาบให้ตรวจตารางสอน วันเริ่มเรียน และทะเบียนวิชาของห้องนั้น หรือเพิ่มคาบชดเชย/เช็กชื่อเพิ่มเติม ระบบไม่ให้บันทึกเช็กชื่อในวันที่ยังมาไม่ถึง

ลิงก์นักเรียน

ใน จัดการ เลือกวิชาและห้องก่อนสร้างลิงก์ มีลิงก์ดูคะแนนแบบอ่านอย่างเดียวกับลิงก์ส่งรูปแยกกัน แจกหนึ่งลิงก์ต่อวิชา/ห้อง เช่น วิทยาการคำนวณ ม.2/1 และคอมพิวเตอร์ ม.2/1 ใช้คนละลิงก์

นักเรียนเปิดลิงก์ส่งงาน ค้นหา/เลือกชื่อ ยืนยัน เลือกชิ้นงาน ถ่ายรูปหรือเลือกรูป ตรวจภาพและส่ง ภาพเก็บใน Drive ตามวิชา/ห้อง/งาน ครูดูที่ คะแนน > รูปและสถานะส่งงาน การส่งครั้งแรกที่ยังไม่มีคะแนนได้เต็ม หากมีคะแนนเดิมจะไม่เขียนทับ ภาพซ้ำ/คล้ายมีธงให้ครูตรวจ ไม่หักคะแนนเอง

ลิงก์ส่งงานยังใช้การเลือกชื่อ ครูควรให้นักเรียนเขียนชื่อ ห้อง เลขที่ และชื่องานลงบนกระดาษด้วย ส่วนลิงก์ดูคะแนนห้องแสดงข้อมูลในห้อง/วิชาที่กำหนด จึงควรแจกให้กลุ่มที่ต้องการให้เห็นข้อมูลนั้นเท่านั้น

รายงานและสำรอง

เปิด รายงาน เลือกวิชา/ห้องแล้วโหลดรายงาน ใช้ปุ่มพิมพ์และเลือก Save as PDF ได้ ตรวจเกณฑ์คะแนนและเวลาเรียนก่อนออกผลจริง ดาวน์โหลดสำรอง JSON จาก ย้ายข้อมูล เก็บไว้ส่วนตัว โดยรูปยังอยู่ใน Google Drive ไม่ได้ฝังรวมใน JSON

ใช้ URL เดียวกันบนมือถือ แท็บเล็ต และโน้ตบุ๊ก เมื่อเปิดค้างหลายอุปกรณ์ให้กดรีเฟรชก่อนแก้ข้อมูลล่าสุด ระบบใช้การเชื่อมต่ออินเทอร์เน็ตในการบันทึก
